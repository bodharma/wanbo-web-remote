# Wanbo Web Remote

[English](README.md) · **Українська**

Локальний браузерний пульт для Android-проєктора через Wi-Fi та ADB. Кнопки навігації, гучність, Unicode-текст, відносна миша та запуск Jellyfin / SmartTube / Kodi. Знімок екрана оновлюється за запитом; постійного кодування відео немає.

Інтерфейс має перемикач **English / Українська**. Мова спочатку визначається за браузером, а вибір зберігається локально. Зміна мови не очищає введений текст.

## Що потрібно

Docker із Compose v2 та доступ контейнера до мережі проєктора. На Mac підійде запущений OrbStack або Docker Desktop. На проєкторі має бути вже доступний ADB через TCP, зазвичай порт `5555`; увімкнення Developer options саме по собі цього не гарантує. Для миші потрібен доступ ADB shell до `/dev/uhid`.

Проєктор має бути увімкненим. Пульт перевіряє його ADB-серійний номер перед керуванням. Серійний номер із наклейки може відрізнятися від `ro.serialno`.

## Встановлення і перший запуск

1. Скопіюйте репозиторій і шаблон налаштувань:

   ```sh
   git clone https://github.com/bodharma/wanbo-web-remote.git
   cd wanbo-web-remote
   cp .env.example .env
   ```

2. У `.env` замініть `PROJECTOR_HOST` на адресу свого проєктора. Значення `192.0.2.10` у шаблоні — лише приклад. Якщо локальний порт зайнятий, змініть `WEB_PORT`, наприклад на `8766`.

3. Завантажте готовий публічний образ:

   ```sh
   docker compose pull
   ```

4. Отримайте ADB-серійний номер, не запускаючи вебсервіс:

   ```sh
   docker compose run --rm --no-deps --entrypoint sh remote -c \
     'adb connect "$PROJECTOR_HOST:$PROJECTOR_PORT" && adb -s "$PROJECTOR_HOST:$PROJECTOR_PORT" shell getprop ro.serialno'
   ```

   Якщо на проєкторі з'явиться запит авторизації ADB, дозвольте цей комп'ютер і повторіть команду. Запишіть отримане значення в `PROJECTOR_SERIAL` у `.env`.

5. Запустіть пульт:

   ```sh
   docker compose up -d --no-build
   ```

   Відкрийте **http://127.0.0.1:8765** або порт зі свого `WEB_PORT`. Використовуйте саме `127.0.0.1`: перевірка Host відхиляє іншу адресу.

Файл `.env` містить локальні налаштування й виключений із Git та контексту Docker-збірки. Передавати його до репозиторію не потрібно.

## Готовий образ у GHCR

Образ: `ghcr.io/bodharma/wanbo-web-remote:0.1.0`. Код та образ публічні. Акаунт GitHub, токен і вхід у registry не потрібні:

```sh
docker pull ghcr.io/bodharma/wanbo-web-remote:0.1.0
```

Доступні платформи опублікованого образу: `linux/arm64` та `linux/amd64`. Для збірки з коду замініть `docker compose pull` у setup на `docker compose build`. Обидва варіанти використовують той самий `.env` і команду запуску.

## Керування

| Дія | Як виконати |
| --- | --- |
| Навігація | Кнопки на сторінці або стрілки + Enter |
| Назад / додому | Кнопки або Esc / Home / фізична клавіша H |
| Текст | Виберіть поле на проєкторі, введіть текст у браузері, натисніть «Вставити» |
| Миша | «Керувати мишею», далі рух, кліки й колесо; Esc повертає курсор комп'ютеру |
| Знімок | «Оновити екран»; це окремий знімок, який сам не оновлюється |

Текст вставляється через буфер обміну проєктора, замінюючи його попередній вміст; буфер комп'ютера не зчитується. Підтвердження протоколу не гарантує, що конкретний застосунок прийняв вставлення. Текст не записується в журнали чи localStorage. Ліміт — 4096 байтів UTF-8.

Миша працює як відносний віртуальний HID-пристрій: орієнтуйтеся на курсор на екрані проєктора. Кліки по знімку не пересилаються. Є лівий / правий клік і вертикальна прокрутка; перетягування не реалізоване. Захоплення курсора потребує підтримки Pointer Lock у браузері.

Швидкі кнопки очікують уже встановлені пакети `org.jellyfin.androidtv`, `app.smarttube.fdroid`, `org.xbmc.kodi`. Список дозволених пакетів — `APPS` у `web_remote.py`. Натискання відкриває застосунок без примусового закриття або автоматичного запуску відео.

## Налаштування

| Змінна | Значення |
| --- | --- |
| `PROJECTOR_HOST` | Обов'язкова адреса проєктора |
| `PROJECTOR_PORT` | TCP-порт ADB, типово `5555` |
| `PROJECTOR_SERIAL` | Обов'язковий точний результат `getprop ro.serialno` |
| `WEB_PORT` | Локальний порт браузера, типово `8765` |
| `IMAGE` | Образ для Compose, типово `ghcr.io/bodharma/wanbo-web-remote:0.1.0` |

Compose автоматично узгоджує `WEB_ORIGIN` із зовнішнім портом. Для власного `docker run` задайте `WEB_ORIGIN` явно, якщо змінюєте порт публікації. Усередині контейнера HTTP слухає `0.0.0.0:8765`; Compose публікує його лише на `127.0.0.1` хоста.

## Обслуговування

```sh
docker compose ps
docker compose logs --tail=50 remote
docker compose exec remote sh -c 'tail -n 50 /var/lib/wanbo-remote/device.log'
docker compose restart
docker compose down
```

Після перезапуску сервісу оновіть сторінку: її захисний токен змінюється. ADB-ключі та журнал пристрою зберігаються в Docker volumes. Звичайний `docker compose down` їх залишає. Healthcheck перевіряє вебсервіс без звернення до проєктора; статус `healthy` не означає доступність ADB.

Якщо пульт показує помилку зв'язку, перевірте адресу, порт ADB, авторизацію та `PROJECTOR_SERIAL`. При зміні DHCP-адреси оновіть `.env` і виконайте `docker compose up -d --no-build`. Для `No route to host` / timeout перевірте доступ Docker до локальної мережі та відсутність ізоляції Wi-Fi-клієнтів. Якщо миша не рухається, журнал пристрою покаже помилку доступу до UHID; нові права на проєкторі автоматично не надаються.

На macOS перевірте **System Settings → Privacy & Security → Local Network**: дозволи можуть бути окремими для **OrbStack** та **OrbStack Helper**. Після зміни дозволу повністю закрийте застосунок OrbStack і відкрийте знову: перезапуск лише Docker VM може не застосувати дозвіл. Це тимчасово перерве інші його контейнери.

## Межі доступу

Логіну для віддалених користувачів немає. Залишайте стандартну публікацію на loopback; не виставляйте порт у LAN або інтернет без окремої автентифікації та HTTPS. API перевіряє Host, Origin і токен сторінки та дозволяє лише визначені команди. Контейнер працює без root, з read-only файловою системою, без Docker socket, USB, privileged mode або host networking.

На Android запускається офіційний тимчасовий сервер scrcpy з вимкненими відео, аудіо та автоматичною синхронізацією clipboard. Wi-Fi, ADB-налаштування та прошивка не змінюються. Знімки створюються у приватному каталозі й прибираються після передачі; якщо мережа зникла під час прибирання, приватний тимчасовий файл може залишитись до ручного очищення.

## Розробка

Потрібні Python 3.14 і Node.js для перевірки браузерного коду:

```sh
python3 -m unittest discover -s tests
node tests/test_web_keyboard.cjs
```

У тестах використовуються вигадані адреса й ідентифікатор; з'єднання з реальним проєктором не потрібне. `Dockerfile` закріплює базовий образ за digest та перевіряє SHA-256 офіційного scrcpy server 5.0.1. Походження й ліцензії компонентів — у [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).
